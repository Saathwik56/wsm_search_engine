1. Executive Summary & Problem Definition

Information Retrieval (IR) is the science of searching for documents, information within documents, and metadata about documents. In modern Web Search and Mining (WSM) systems, constructing efficient, scalable, and mathematically sound indexing and retrieval pipelines is fundamental.

The objective of this assignment is to engineer a production-grade, modular Information Retrieval system from scratch. In accordance with strict software engineering specifications, the project enforces clean separation of concerns across seven standalone modules:

  1. Document Loading: Automated file discovery, character decoding, and document abstraction.
  2. Tokenization: Lexical boundary segmentation with positional offset tracking.
  3. Text Normalization / Case Folding: Canonicalization of characters, accents, stopwords, and morphological stemming.
  4. Inverted Index Construction: High-performance positional postings list mapping words to document locations.
  5. Query Processing: Multi-paradigm evaluation supporting Boolean logic, exact phrase chains, and TF-IDF ranking.
  6. Wildcard Processing: Advanced sub-string indexing via the classical Permuterm and K-gram architectures.
  7. Frontend GUI: Intuitive desktop interface with dedicated search input, search button, and read-only result presentation.
Architectural Constraint: Pure Standard Library
To guarantee that the solution is completely self-contained and universally executable on any standard Python 3.8+ installation without requiring external packages (such as NLTK, Scikit-Learn, or PyTorch), all algorithms—including the Porter Stemmer, the Shunting-Yard Boolean parser, the Permuterm Index, and the Positional Inverted Index—have been designed and implemented directly using Python's native standard library.

3. Detailed Implementation of Required Modules

3.1. Module 1: Document Loading (src/document_loader.py)

The DocumentLoader class handles the discovery, decoding, and representation of text files. Documents are encapsulated within a strongly typed Document dataclass: 

@dataclass
class Document:
    doc_id: int               # Unique integer document identifier (1, 2, 3...)
    title: str                # Human-readable title (defaults to filename)
    path: str                 # Canonical filesystem path
    content: str              # Complete raw textual body
    metadata: Dict[str, str]  # Arbitrary metadata dictionary

Key Engineering Features:

  • Multi-Encoding Detection: Files are read by attempting utf-8, utf-8-sig, latin-1, and cp1252 in sequence, falling back to errors="replace" so that corrupt or non-standard characters never crash index construction.
  • Deterministic Sorting: Directory traversal orders filenames alphabetically before assigning IDs, ensuring reproducibility across runs and environments.
  • In-Memory Addition: Supports add_text_document(title, content) for dynamic document creation without touching the hard drive (used extensively in unit testing).

3.2. Module 2: Tokenization (src/tokenizer.py)

The Tokenizer class segments raw unstructured text into atomic Token instances. Unlike rudimentary splitters, it captures positional and character-level boundaries: 

@dataclass
class Token:
    text: str           # String representation of token
    position: int       # Zero-indexed word index in doc (0, 1, 2...)
    start_char: int     # Character start offset in raw content
    end_char: int       # Character end offset in raw content

Dual Regular Expression Patterns:

  • Document Pattern: r"[a-zA-Z0-9]+(?:'[a-zA-Z0-9]+)?" extracts alphanumeric words, numbers, and contractions (e.g. don't, user's).
  • Query Pattern: r"[a-zA-Z0-9*?]+(?:'[a-zA-Z0-9]+)?" retains wildcard markers (* and ?) during search query analysis so wildcards are not inadvertently stripped before query evaluation.

3.3. Module 3: Text Normalization & Case Folding (src/normalizer.py)

Normalization bridges the gap between lexical variations in queries and documents. The TextNormalizer coordinates four distinct transformations:

  1. Case Folding: Invokes str.lower() across all tokens, ensuring case-insensitive retrieval.
  2. Unicode Normalization: Decomposes composite characters via Unicode NFKD normalization and strips non-spacing combining characters (e.g. converting résumé to resume).
  3. Punctuation Stripping: Removes peripheral delimiters (`~!@#$%^&*()-_=+[{]}\\|;:'",<.>/?) while retaining valid alphanumeric characters.
  4. Stopword Filtering: An internal set of 120+ standard Information Retrieval stopwords can be filtered out when enabled.
  5. Porter Stemmer Algorithm: Built-in implementation of Martin Porter’s 1980 algorithm consisting of:
    • Step 1a & 1b: Plural forms and past participles (e.g., sses $\rightarrow$ ss, ies $\rightarrow$ i, eed $\rightarrow$ ee).
    • Step 1c: Terminal y replacement (y $\rightarrow$ i following a consonant).
    • Step 2: Double suffixes (e.g., ational $\rightarrow$ ate, ization $\rightarrow$ ize).
    • Step 3: Suffix transformations (e.g., alize $\rightarrow$ al, icate $\rightarrow$ ic).
    • Step 4: Complex suffix removal (e.g., ement, able, ible).
    • Step 5a & 5b: Final -e and double -l elimination.

3.4. Module 4: Positional Inverted Index (src/inverted_index.py)

The InvertedIndex class maps each normalized vocabulary term to an ordered list of Posting records: 

@dataclass
class Posting:
    doc_id: int                  # Document containing the term
    term_frequency: int          # Count of term occurrences in this document
    positions: List[int]         # Ordered token offsets [p1, p2, p3, ...]

The positional index maintains the document lengths table (total tokens per document) required for length-normalized ranked scoring and supports complete JSON disk persistence via save_to_file() and load_from_file().

3.5. Module 5: Query Processing Engine (src/query_processor.py)

Supports four major retrieval paradigms:

  • Boolean Parsing via Shunting-Yard Algorithm: Converts infix expressions containing AND, OR, NOT, and parentheses into Reverse Polish Notation (RPN). Automatically inserts implicit AND conjunctions between adjacent operands (e.g. web search $\rightarrow$ web AND search) and between an operand and NOT (e.g. index NOT permuterm $\rightarrow$ index AND NOT permuterm). Postings lists are intersected using a linear-time two-pointer algorithm.
  • Positional Phrase Search: Evaluates quoted expressions (e.g., "inverted index"). The engine identifies documents containing all terms, inspects their position lists, and validates that consecutive tokens appear at adjacent word indices ($pos_{k+1} = pos_k + 1$).
  • Ranked Free-Text Retrieval: Employs sublinear TF-IDF scoring normalized by the square root of the document length.
  • Dynamic Context Snippets: Computes a 180-character window around the densest matching term cluster, snaps boundaries cleanly to word breaks, and encapsulates matching terms in bracket markers for GUI highlighting.

3.6. Module 6: Wildcard Processing (src/wildcard_processor.py)

Wildcard expansion avoids sequential scanning of the vocabulary by employing auxiliary sub-string indices:

  1. Permuterm Index:
    • Appends the special end-of-word sentinel $ to each vocabulary term.
    • Generates all cyclic permutations. For example, for hello$: 
      hello$, ello$h, llo$he, lo$hel, o$hell, $hello
    • Queries are rotated until the asterisk * is at the right-hand side, converting wildcard matching into a prefix lookup:
      • Trailing wildcard X* $\rightarrow$ rotated to $X* (lookup prefix $X)
      • Leading wildcard *X $\rightarrow$ rotated to X$* (lookup prefix X$)
      • Middle wildcard X*Y $\rightarrow$ rotated to Y$X* (lookup prefix Y$X)
    • Prefix lookup uses binary search (bisect) over alphabetically sorted keys in $O(\log V)$ time.
  2. K-Gram (Trigram) Index: Pads terms with $term$, extracts 3-character character n-grams, intersects candidate vocabulary lists, and eliminates false positives via regular expression post-filtering.

The result area features rich color-coded tagging for document titles, match scores, file metadata, wildcard expansion alerts, and yellow highlighted snippet words.
  • Corpus Bar: Path selector with a native "Browse..." folder dialog and a "Rebuild Index" button.

4. Mathematical Models & Algorithmic Formulations

4.1. Positional Phrase Intersection Algorithm

For a phrase query consisting of ordered terms $t_1, t_2, \dots, t_k$, a document $D$ is a match if and only if there exists a sequence of positions $(p_1, p_2, \dots, p_k)$ such that $p_i \in \text{positions}(t_i, D)$ and:

p_{i+1} = p_i + 1 \quad \forall \, 1 \le i < k

4.2. Logarithmic TF-IDF Relevance Scoring

For free-text ranked queries, each candidate document $D$ is scored against query $Q$ using sublinearly scaled term frequency and smoothed inverse document frequency:

\text{Score}(D, Q) = \frac{1}{\sqrt{\text{Length}_D}} \sum_{t \in Q \cap D} \left(1 + \ln(\text{TF}_{t, D})\right) \cdot \ln\left(1 + \frac{N}{\text{DF}_t}\right)

Where:

  • $\text{TF}_{t, D}$ is the term frequency of term $t$ in document $D$.
  • $\text{DF}_t$ is the document frequency (number of documents containing term $t$).
  • $N$ is the total number of documents in the collection.
  • $\text{Length}_D$ is the token count of document $D$ (providing cosine-like length normalization to prevent bias toward longer documents).

4.3. Shunting-Yard Boolean Parsing Algorithm

Dijkstra's Shunting-yard algorithm converts infix boolean expressions to postfix (RPN) using an operator stack and output queue:

Operator Precedence Associativity Description
NOT 3 (Highest) Right-to-Left (Unary) Complement / Universal Set Difference ($U \setminus S$)
AND 2 Left-to-Right (Binary) Two-pointer Postings List Intersection ($S_1 \cap S_2$)
OR 1 (Lowest) Left-to-Right (Binary) Two-pointer Postings List Union ($S_1 \cup S_2$)
( ... ) N/A Delimiter Forces nested sub-expression evaluation override
